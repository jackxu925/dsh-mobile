任意内容引用 · 方案原型

目标：对话里任何内容——你自己的话、agent 的回答、工具调用、命令输出——都能变成「引用」，加一句自己的注解， 一条消息里可带多条引用，作为下一轮的上下文。
调研结论：Codex 是「选中文本 → Add to chat」（[codex#37560](https://github.com/openai/codex/issues/37560)），微信是「引用条前置」， Claude Code 目前还没有像样的原生引用 UI（[claude-code#26716](https://github.com/anthropics/claude-code/issues/26716)）。
协议上限（已核实）：DSH 的 prompt 只收 text / image / file 三种块，没有结构化引用类型。 所以引用最终都会拼进文本发给模型——原型里每个方案都有「发送预览」，所见即模型所得。
A chips + 注解（推荐）B 微信式引用条C 选段引用对比

三个方案对比

方案引用入口引用形态注解多引用主要取舍
A chips + 注解（推荐）点按任意内容出操作条输入框上方一排 chips（类型图标+摘要）点 chip 单独加✓ 横滑并列交互最全，实现也最大（约 350 行）
B 微信式引用条同上输入框上方堆叠条（原文+✕）写在正文里✓ 堆叠最简单（约 150 行），但多引用时占地方、注解和引用不挂钩
C 选段引用长按选择文本片段精确到片段同 A✓最精准但手机上选择文本很费手，适合作为 A 的后续增强

我的建议：A，发送编排用「引用块 + 【注】」

发送时自动拼成（发送预览里就是实物）：
> [用户] 周转率按门店在售天数对齐，别按自然月
【注】按这个口径继续

> [工具·bash] python extract_store_structure.py
【注】数据源入口

把口径说明补进页面
引用块用 markdown 的 >（app 里本来就会渲染成竖线引用样式），来源标 [用户]/[助手]/[工具·名]，注解用【注】紧跟其后——模型读得懂，人也看得懂。
